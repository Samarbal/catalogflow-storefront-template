# Client storefront setup

1. **Collect approved content.** Obtain the business name and wordmark, bilingual copy, location, contact details, delivery terms, product list, prices, availability, product photography, and confirmed commercial usage rights. Treat the LUNA content as fictional sample copy.
2. **Configure the business.** Edit `src/config/store.ts`: wordmark, contact and social details, colors, currency and locale, WhatsApp greeting, hero, story, featured, catalog, footer, delivery, and categories. The original color values preserve the LUNA demo design. Update every business claim and date.
3. **Configure products.** Edit `src/data/products.ts`. Give every product a unique stable `id`, positive price in the configured currency, category matching a configured category ID, both language versions, image, notes, availability, and optional `featured`. Product counts and price filter bounds derive from this array. Set `story.image` separately in store configuration.
4. **Review shared translations.** Edit `src/content/copy.ts` if the business needs different interface wording. Keep both languages complete. The content files hold words the shopper reads; `src/App.tsx` should not need editing for a normal client setup.
5. **Update site metadata.** Edit `.figma/make/site.json` for the client title, description, primary language, favicon, and indexing decision. Replace `public/favicon.svg` with the client's approved icon. Keep indexing disabled until the client approves publication and content rights.
6. **Verify assets.** Follow `ASSETS.md`; replace every demo product and story image with a photo of the actual offered product. Preserve image aspect ratios to keep the layout. Record the source and permissions for each asset.
7. **Configure inquiries last.** The fictional LUNA demo keeps `isDemo: true` while `whatsapp.enabled: true` opens a draft to `970597054114`. Its message starts with a demo prefix and says it is not a real purchase. For a real client, replace all fictional details and assets, verify the business-owned number in international digits without spaces or `+`, edit `whatsapp.number` and bilingual message fields, set `isDemo: false`, then choose whether `whatsapp.enabled` is true. Test the destination and draft in both languages. Opening the link does not send the message; the merchant must confirm any real order.
8. **Check and deliver.** Run `corepack pnpm install --frozen-lockfile`, `corepack pnpm typecheck`, `corepack pnpm test`, `corepack pnpm format:check`, and `corepack pnpm build`. Check desktop and mobile widths, keyboard navigation, Arabic direction, product totals, and all contact links before sharing a preview. Do not publish a client site until the client approves content and deployment.

The cart uses the browser key `catalogflow-cart`. If product IDs change, old cart entries are discarded safely. Cart data is local to each browser and is not an order record.
